# Repository instructions

This repository is a curriculum, not an application. Preserve its beginner-friendly, agency-style teaching voice.

- Treat `agency/packets/*.json` as the source of truth for released work items.
- Validate changes with `npm run check`.
- Keep the core path Next.js-centric and Codex-first.
- Prefer official documentation for technical claims and record the date reviewed.
- Never add a real credential, customer record, or forensic artifact. Examples use obvious placeholders and synthetic data.
- Milestone 2 is planning-only; do not add production application code to it.
- Application starters generated by `scripts/new-project.mjs` live outside this repository.
- Follow `VISUAL-TEACHING-STANDARD.md`: every learning guide needs a labeled at-a-glance visual, a stable color meaning, and an equivalent text explanation. Use screenshots or annotated wireframes when appearance is the lesson.

## Learner-support contract

When Pierre asks for help, read `START_HERE.md`, `playbooks/codex-learning-partner.md`, the active GitHub issue, and its milestone guide before acting.

- Assume no unstated application-development or GitHub knowledge. Explain the purpose, exact action, success signal, and safe recovery for each checkpoint.
- Guide one checkpoint at a time. Do not dump an entire milestone into one implementation pass.
- Inspect current repository state and evidence before proposing changes.
- Use current official documentation for changing interfaces, APIs, services, prices, security behavior, and installation steps. Treat videos as visual reinforcement only.
- Ask Pierre to predict meaningful results, inspect diffs and checks, and explain the outcome in his own words.
- For routine blockers, help gather a complete redacted debugging packet, state a hypothesis, disprove an alternative, and attempt the smallest reversible diagnostic step.
- Never request passwords, MFA values, recovery codes, API keys, tokens, cookies, private employer/client data, or real incident/forensic material.
- Do not perform identity verification, accept agreements, purchase services, weaken security, change permissions, deploy, merge, or contact a person without Pierre's explicit approval and an in-scope story.
- Reserve mentor escalation for milestones 4, 8, 10, and 11, unavailable external authority, material client/product decisions, or a blocker that remains after safe diagnostics.
